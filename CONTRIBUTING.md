# Contributing

Help make workshop assistants easier to understand and harder to overclaim.

Good contributions: invented failure cases, clearer role boundaries, accessibility/mobile improvements, translations, and small reproducible test fixes.

1. Use entirely synthetic data. Do not upload customer conversations, real VINs/plates, private manuals, tokens or company source code.
2. Describe expected behavior and the actual result, with a minimal sample.
3. Run `npm test` after code changes. Keep tests focused on behavior, not implementation snapshots.
4. Keep authored scenarios labeled as authored; do not describe them as model evaluations.

No unsolicited promotion, purchased stars, fake testimonials or issue spam. An actionable critique is more valuable than a popularity number.
